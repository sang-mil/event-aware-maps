# 백엔드 아쉬운 점과 남은 과제 (2026-11-27 기준)

2025년 자료를 다시 검증한 기록입니다. 이 문서의 남은 항목은 현재 코드·로컬 데이터에서 확인한 상태입니다.

## 1. 아직 만들지 않은 것
| 항목 | 상태 | 비고 |

## 2. 정확도 한계
| 지표 | 값 | 원인·개선 방향 |
|---|---|---|
| 혼잡 단계 적중률 (공연 날, 4개 역, 19~23시) | 시간순 검증 58% (기준선만 52%), 122일 2,440건 | 각 예측 날짜보다 앞선 자료만 학습하는 `as_of` 검증. leave-one-out 60%는 미래 기록도 학습하므로 참고값일 뿐 |
| 실제 혼잡을 미리 잡은 비율 | 시간순 검증 50% | 끝나는 시각 추정이 빗나간 날, KSPO 기록에 없는 행사 |
| 가장 많은 오답 | 실제 '여유'를 '보통'으로 574건 | **주말 기준선을 월~목으로 대신**함(2025년 공연 없는 토요일 1일, 일요일 0일). 주말 보정에는 추가 관측이 필요 |
| 공연이 겹친 날 | 시간순 검증 58일·1,160건에서 적중 51%, 단독 공연 64일·1,280건에서 64%. 혼잡 재현율은 겹침 47%, 단독 52% | 현재 모델은 겹친 퇴장 기록을 계수 학습에서 제외. 이전 겹침일로 배율을 보정하는 실험은 적중률 51.1%→51.5%에 그쳤고 평균 인원 오차는 381명→528명으로 커져 적용하지 않음. 차량별 출차 기록을 확보한 뒤 다시 검증 |
| 끝나는 시각 추정 | 71% 일치 (승차 최고 시각과 같거나 1시간 앞) | 낮 공연·종일 축제에서 빗나감. 입출차 데이터로 개선 가능 |
| 추천 1순위와 실제 최선의 일치율 | 시간순 검증 62% (610건 중 379건) | `recommend-backtest`로 재현 가능. 각 날짜 이전 자료로 예측하고, 실제 승차 기준으로 같은 후보들을 비교 |
| 검증 방식 | `as_of` 날짜순 검증을 기본값으로 적용 | 과거 날짜별 결과 생성에도 예측 날짜 이후 자료가 들어가지 않도록 수정. 테스트에서 미래 기록을 바꿔도 과거 검증 결과가 같은지 확인 |

## 3. 데이터 한계
- **2025년 자료뿐**: KSPO 연계 데이터가 2025년(358일)이라 화면은 2025 리플레이. 앞으로의 공연 일정은 없음. 공연정보 API(KSCperf)는 2024년까지의 보관 자료.
- **공연장 없음**: 연계 데이터에 공연장이 없어 `venue_id`는 null, 출발지는 올림픽공원 지역 하나로 묶음.
- **시작 시각 없음**: `start_at` null.
- **KSPO "방문객" 값 주의**: 7,803개 시간대 중 2,579개(33%)에서 방문객이 정확히 주차대수 × 5. 실제로 센 값이 아닐 수 있어 계산에 쓰지 않음.
- **KSPO 연계 데이터 빈 곳**: 1년 8,760시간 중 약 950시간 없음. 강수량 6,692개 시간대 빈 칸(비 없음인지 모름인지 불명).
- **승하차 빈 칸**: 1~8호선 CSV 하차 빈 칸 576개(0으로 채우지 않음). 06시 이전·24시 이후는 묶음 값(-1, 24).
- **막차·출구 정보**: 자료 없음 → null, 화면은 "정보 없음". 도보 시간·거리·좌표는 카카오 API를 이용한 사전 발행 코드까지 구현했으며, 첫 API 호출과 화면 확인은 배포 키 설정 후 남아 있음.
- **공연장 "가까운 역" 짝**: 프런트 디자인 목업 값을 따름. 공식 자료로 재확인 안 함.
- **목적지 무관**: 도착역별 경로 자료가 없어 귀가 비교가 목적지에 따라 달라지지 않음.

## 4. 범위 한계
- 혼잡 예상은 **19~23시만**. 그 밖에 끝나는 공연 23건은 "정보 없음" 안내.
- 역 순위·귀가 선택지는 **올림픽공원 쪽 역만**. 몽촌토성·한성백제는 "가까운 역"에 없어 귀가 선택지에서 빠짐.
- 잠실 쪽 역(종합운동장·잠실새내)은 예상은 내지만 야구 등 다른 행사 영향이 섞여 검증·순위에서 제외.
- 문구 "N배"는 기준선이 작으면 크게 보임(예: 7.5배).

## 5. 운영
- 승하차 요약 파일(`data/seed`)은 원본이 새로 나올 때(1년 또는 분기) **사람이 직접** 내려받아 `export-seed`로 갱신.
- KSPO API는 **5초에 1번** 제한. 수집기는 6초 간격·재시도로 대응.
- GitHub Actions 스케줄은 몇 분 늦을 수 있고, 공개 저장소는 60일간 활동이 없으면 스케줄이 멈출 수 있음.
- 서울 지하철 API는 `http://`만 지원해 인증키가 암호화되지 않고 전송됨(제공 방식).
