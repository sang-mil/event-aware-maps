## 1. 목적

올림픽공원과 잠실에서 공연이나 경기가 끝날 무렵, 관람객과 주민이 **어느 역에서 몇 시에 타면 덜 붐빌지** 예상 정보를 보고 귀가 방법을 고를 수 있게 한다.

## 2. 목표와 성공 지표

| 목표 | 지표 | MVP 목표값 (가설) |
|---|---|---|
| 덜 붐비는 선택을 돕는다 | 귀가 방법 비교에서 추천 방법을 고른 비율 | 40% 이상 |
| 예상이 맞는다 | 귀가 후 피드백 중 예상 단계와 체감이 일치한 비율 | 60% 이상 |
| 예상이 평소 기준보다 낫다 | 검증 날짜에서 행사 반영 예상의 오차 / 평소 기준선 오차 | 1 미만 |
| 행사 날 다시 쓴다 | 알림을 받은 사용자 중 알림을 눌러 연 비율 | 30% 이상 |
| 미리 대비한다 | 캘린더에서 날짜를 고른 뒤 역 상세나 공연 상세로 간 비율 | 25% 이상 |

목표값은 공모전 이후 실제 사용 데이터로 다시 정한다.

## 3. 사용자와 사용자 스토리

| ID | 사용자 | 스토리 |
|---|---|---|
| US-1 | 관람객 | 공연이 끝나기 전에, 지금 역으로 가면 얼마나 붐빌지 알고 싶다. |
| US-2 | 관람객 | 바로 탈지, 늦게 탈지, 옆 역까지 걸을지 비교해서 고르고 싶다. |
| US-3 | 관람객 | 막차가 가까우면 기다리라는 안내는 받고 싶지 않다. |
| US-4 | 관람 예정자 | 공연 날 근처 역이 몇 시에 붐빌지 미리 보고 알림을 걸어 두고 싶다. |
| US-5 | 인근 주민 | 행사가 있는 날을 미리 알고 외출 시간을 피하고 싶다. |
| US-6 | 모든 사용자 | 위치나 알림을 허용하지 않아도 기본 정보는 보고 싶다. |
| US-7 | 아이폰 사용자 | 아이폰에서도 알림을 받는 방법을 알고 싶다. |

## 4. 범위

### 포함 (MVP)

- 첫 실행 안내와 위치·알림 권한 요청
- 하단 탭 3개: 홈, 길찾기, 캘린더
- 근처 역 시간대별 예상 혼잡, 역 상세
- 오늘 공연·경기 목록, 공연 상세, 경기 상세(진행 상태만)
- 행사 캘린더 (올림픽공원 6곳, 잠실 6곳)
- 귀갓길 찾기, 귀가 방법 비교, 경로 상세
- 웹 푸시 알림, 아이폰 홈 화면 추가 안내, 휴대폰 캘린더 추가(.ics)
- 귀가 후 피드백
- 설정, 개인정보 처리방침, 이용약관
- 예외 상태 E1~E8

### 제외

- 실시간 경기 점수와 중계
- 회원가입, 로그인, 즐겨찾기 서버 저장
- 열차 안 혼잡도, 실시간 대기 시간
- 버스, 택시, 자가용 경로
- 지난 날짜의 실제 기록 조회 (예상만 보여준다)

## 5. 정보 구조

하단 탭: **홈 / 길찾기 / 캘린더**. 현재 탭은 아이콘과 글자를 보라색(#4E3DBC)으로 표시한다. 상세 구조는 서비스기획서 5장과 캔버스 '최종본 IA'를 따른다.

우선순위: **P0** 공모전·MVP 필수, **P1** MVP 포함 권장, **P2** 확장

## 8. 혼잡 예상 요구사항

| ID | 요구사항 |
|---|---|
| DR-1 | 평소 기준선: 같은 역, 요일, 시간대의 행사 없는 날 승차 중앙값 |
| DR-2 | 행사 효과: 같은 공연장, 비슷한 규모·종료 시각의 과거 행사일 승차 배수 |
| DR-3 | 예상 = 기준선 × 행사 효과, 한 시간 단위("20시대") |
| DR-4 | 단계: 혼잡 1.5배 이상, 보통 0.8~1.5배, 여유 0.8배 미만, 데이터 없으면 정보 없음 |
| DR-5 | 화면에는 특정 과거 날짜나 출처를 표시하지 않는다. 근거는 이용약관과 기획서에 둔다. |
| DR-6 | 승하차 원자료는 월 단위, 공연 정보는 하루 1회 이상 갱신한다. |
| DR-7 | 서울시 실시간 도시데이터의 올림픽공원·잠실 장소 혼잡(추정 인구)을 홈 '현장 실시간 혼잡'에 역 예상과 구분해 보여준다(연동됨). 이 값으로 당일 역 예상을 보정하는 것은 P2. |
